# Vibe Docing 全功能体验审查

- 日期：2026-08-09
- 项目：`vibe-docing`
- 体验入口：`http://localhost:5173/`
- 测试视口：桌面端 1280×720；移动端 390×844
- 方法：真实浏览器交互、可见 DOM/截图检查、失败请求抓包、源码定位、现有测试回归
- 测试树：`UX 体验审查（已验证重命名）`

## 结论

当前版本不适合继续打磨局部视觉后直接交付。首要问题是一处系统性 API 客户端缺陷，它让节点删除、树删除、节点恢复、版本回退和智能路由全部失败；此外，停止生成并不会真正停止请求，移动端无法有效使用，长分支标题会挤爆右栏。

建议按以下顺序修复：

1. 修复无 body 请求的 Header，并补一条前后端集成测试。
2. 实现真正的取消生成，统一流式状态。
3. 明确树删除是否可恢复；若文案承诺可恢复，必须补齐恢复入口。
4. 接回智能路由流程，或删除不可用入口与描述。
5. 修复移动端信息架构、长标题和跨树状态污染。
6. 收敛图片、笔记、选区菜单等交互语义。

## P0：无 body 请求全部被 Fastify 拒绝

### 用户表现

- 版本回退：点击“回退”后显示“版本回退失败”。
- 节点删除：确认后显示“删除失败，请稍后重试”。
- 树删除、节点恢复、智能路由具有相同风险。

### 实际抓包

节点删除请求：

```text
DELETE /api/nodes/VnJsnIv2FkTENdPuMJsjd
Content-Type: application/json
body: <empty>
```

响应：

```json
{
  "statusCode": 400,
  "code": "FST_ERR_CTP_EMPTY_JSON_BODY",
  "error": "Bad Request",
  "message": "Body cannot be empty when content-type is set to 'application/json'"
}
```

### 根因

`packages/web/src/api/client.ts` 的 `json()` 对所有请求无条件设置：

```ts
headers: {
  'content-type': 'application/json',
  ...(init?.headers ?? {}),
}
```

以下方法没有 body，却会携带 JSON Content-Type：

- `deleteNode`
- `deleteTree`
- `restoreNode`
- `revert`
- `route`

### 修复要求

- `init.body === undefined` 时不要设置 JSON Content-Type。
- 不要用补空对象的方式掩盖问题；Header 应反映真实请求体。
- 增加客户端测试，断言无 body 请求没有 `content-type`。
- 增加一条经过真实 Fastify/Vite 代理的集成测试，覆盖 DELETE 和无 body POST。

### 验收

- 节点删除、撤销、回收站恢复、树删除、版本回退、路由均不再返回 400。
- UI 不再显示泛化失败提示。
- Node 22 下全量测试通过。

## P0：树删除承诺可恢复，但产品没有恢复能力

### 用户表现

删除树确认框写着“可在回收站恢复”。实际上：

- 回收站 API/面板只处理节点。
- `tree-repo` 只有 `softDelete`，没有列出已删除树或恢复树的方法。
- 删除成功后树从列表消失，重新加载也无法从 UI 找回。

### 修复要求

二选一，建议选 A：

- A：增加“已删除的树”列表、恢复 API、恢复操作和测试。
- B：如果产品明确不支持恢复，修改确认文案，并把删除风险说清楚。

不要保留“数据库里还在，但用户无法访问”的半恢复状态。

## P1：停止生成不是真正停止

### 复现

1. 在空节点首次提问。
2. 出现“AI 正在思考…”后点击“停止”。
3. 状态条消失、输入框恢复，但回答区仍显示流式光标和“思考中…”。
4. 切换树再回来，后台生成的内容可能已经持久化。

### 根因

`MainDoc.stop()` 只设置 `stopRef` 并修改本地状态：

- 没有 `AbortController`。
- `streamAnswer` 不接受 `AbortSignal`。
- 首次回答时 `transcript` 为空，`patchLastTurn()` 什么也不会更新，主节点继续保持 `streaming`。
- 服务端和 Provider 仍会继续执行并写版本。

### 修复要求

- 每次生成使用独立 `AbortController`，停止时中止 fetch。
- 服务端监听断开/abort，停止 Provider 和工具循环。
- 引入明确的 `cancelled` 或可恢复状态；不要把取消伪装成 `complete`。
- 首次回答和后续轮次共享同一套状态机。
- 增加“停止后不再追加 chunk、不生成完成版本”的端到端测试。

## P1：智能路由在产品中不可用

### 证据

- `parallelAsk.ts` 与 `RoutePrompt.tsx` 只被测试引用，主界面没有导入或渲染。
- `MainDoc.ask()` 始终创建 `kind: 'whole'` 的子节点。
- `api.route()` 是无 body POST，会被 P0 的 Header 缺陷拒绝；错误又被 `parallelAsk` 静默吞掉。

### 用户影响

用户看不到“搬过去/选择落点”流程，也不知道每次追问实际在创建树节点。页面当下展示为线性对话，重新打开树后又表现为层级节点，心智模型不一致。

### 修复要求

- 明确产品选择：恢复智能路由，或正式删除这套死代码和相关产品描述。
- 若保留：接入 `parallelAsk → decideRouteUi → RoutePrompt → migrate`，路由失败应可见但不影响回答。
- 统一“当下多轮展示”和“重新打开后的树结构”。

## P1：移动端不可用

390×844 下测得：

```json
{
  "tree": { "y": 0, "height": 747.96 },
  "main": { "y": 747.96, "height": 1003.97 },
  "sub": { "y": 1751.93, "height": 441.79 },
  "documentScrollHeight": 2193
}
```

三栏在 `max-width: 840px` 时直接纵向堆叠。用户进入页面先看到完整树列表，要滚动约一屏才能到主文档，再滚动两屏才到子文档；输入区也不稳定可达。

### 修复要求

- 移动端改为单主视图：树/主文档/子文档使用顶部切换、抽屉或返回导航。
- Composer 固定在当前主文档底部。
- 不要让导航树内容高度决定主文档起始位置。
- 覆盖 390×844、768×1024 和桌面断点。

## P1：长分支标题挤爆右栏

复杂树中，右侧子文档标签允许整段问题自由换行，卡片标题也没有合理截断。实际页面出现标签占据大量高度、标题与正文堆叠，右栏几乎无法阅读。

### 根因

- `.subdoc-tabs` 使用 `flex-wrap: wrap`。
- 标签按钮没有 `max-width`、省略号或横向滚动策略。
- `.subdoc-card h3` 只设置 `overflow-wrap: break-word`，长标题会占满卡片。

### 修复要求

- 标签使用单行省略，悬停/聚焦展示完整标题。
- 多标签优先横向滚动或可搜索下拉，不要无限换行。
- 卡片标题最多 2–3 行，提供展开入口。

## P1：跨树状态污染

### 已验证

- 在测试树提交一次图片后，“图片仅本地保存，模型暂不读图”会一直显示。
- 切换到完全无关的“本地项目问答”树后，该提示仍然存在。
- 节点删除失败提示也会跨树保留。

### 根因

`ChatBox.showHint` 和 `TreePanel.error` 属于长生命周期组件的本地 state，没有在 `treeId/mainNodeId` 变化时重置。

### 修复要求

- 与节点相关的 composer 状态按 `mainNodeId` 隔离或重置。
- 与树相关的错误按 `treeId` 重置。
- 非阻断提示应自动消失，并允许手动关闭。

## P1：图片提示与真实行为相反

### 已验证

- 粘贴图片会显示缩略图，可移除。
- 带文字提交后缩略图被清空。
- 模型只收到文字。
- 页面却提示“图片仅本地保存，模型暂不读图”。

图片没有保存到节点、笔记或本地附件列表；这条文案会让用户误以为之后能找回图片。

另外，`QuestionEditor` 支持粘贴图片，但重新生成时直接清空图片，没有任何降级提示。

### 修复要求

- 若暂不支持图片：提交前明确提示“图片不会发送或保存”，由用户确认删除或取消。
- 更优方案：把附件持久化到节点/笔记，并在 UI 中可回看；模型是否读图另行标记。
- ChatBox、NotesTab、AnnotationBubble、QuestionEditor 使用同一套附件策略和文案。

## P1：选区操作严重缺乏可发现性

`DocView` 在普通 `onMouseUp` 时只记录 selection；真正打开“笔记/就此展开”菜单的是 `onContextMenu`。普通用户选中文本后不会看到任何操作，需要猜到“保持选区后再右键”。

### 修复要求

- 选中有效文本后，在选区附近直接展示浮动工具条。
- 支持键盘触发并正确管理焦点。
- 右键可保留为补充入口，不应是唯一入口。
- 增加真实浏览器选区 E2E，而不只测 SelectionMenu 组件。

## P2：笔记交互不完整

- 整文笔记保存成功，但点击无锚点笔记不会跳转到任何位置，也没有选中态或反馈。
- 笔记没有编辑、删除入口。
- 只有 Enter 保存，没有显式保存按钮；占位符虽有提示，但移动端输入法下仍不稳妥。

建议：无锚点笔记使用普通卡片选择语义；有锚点笔记才提供“跳到原文”。补编辑、删除和保存反馈。

## P2：空树首屏语义混乱

新建树后立刻出现：

- 文档标题“根”
- 空白“第 1 轮”卡片
- 输入框占位符“继续追问…”

用户其实还没有提出第一问。“继续追问”与空白第一轮都暗示已经发生过一次对话。

建议：首问前隐藏空轮次卡片，标题显示树标题或“开始第一个问题”，Composer 文案改为“输入第一个问题”。

## P2：生成过程缺少工具可见性

读取本地 `package.json` 的请求约等待 30 秒，期间只有“AI 正在思考…”。用户不知道是在排队、读文件、调用模型还是已经卡住。

建议展示阶段：准备上下文、读取文件、模型生成；至少显示耗时与当前工具名，避免暴露敏感参数。

## P2：三栏密度与操作可见性

- 短回答仍占用较高的轮次卡片，三轮短对话就需要内部滚动。
- 6px 分栏把手默认透明，只有悬停才出现背景；双击复位完全没有提示。
- 编辑按钮只在 hover/focus 时出现，触屏设备上难发现。
- 树节点删除按钮依赖 hover，移动端没有可靠 hover。

建议降低短卡片最小高度，给分栏把手提供细线/拖拽指示，确保触屏操作始终可达。

## P2：设置缺少范围与校验

- Provider、Model、Base URL 都是自由文本，保存时不验证 Provider 是否受支持。
- 项目根目录是全局设置；从另一项目切换过来时仍指向旧目录，模型可能回答错误代码库。
- 页面没有明确说明 API Key、Provider 和项目根目录是全局还是当前树级配置。

建议将项目根目录绑定到工作区/树，或至少在树标题附近持续显示当前项目；保存前做 Provider/Base URL/绝对路径校验。

## P2：版本历史可读性不足

版本项只显示 `vN · change_kind`，没有时间、问题摘要、内容预览或 diff。用户无法判断应该回退到哪个版本，合并后尤其危险。

后端已有 diff API，建议在回退前展示差异摘要，并要求二次确认；回退成功后刷新版本列表。

## 测试与工程问题

### 现有测试没有发现 P0

Node 22.21.1 下：

- Server：37 files / 127 tests 通过
- Web：32 files / 120 tests 通过
- Shared：1 file / 3 tests 通过

但线上式浏览器请求仍失败。原因是：

- Web API client 测试 mock `fetch`，只断言 method，不断言无 body 请求的 Header。
- Server 路由测试使用 Fastify `inject`，没有模拟客户端错误 Header。
- 缺少 client → proxy → Fastify 的集成覆盖。

### 默认 Node 版本会让测试完全失败

当前 shell 默认 Node 25.8.1，而项目要求 Node 22.x。直接 `pnpm test` 时，`better-sqlite3` ABI 不匹配，Server 71 项失败；切到 Node 22.21.1 后全部通过。

建议增加 `.nvmrc`/Volta 配置与启动前置检查，让错误在安装或启动时直接说明，而不是产生大量误导性测试失败。

### 测试告警

Web 测试通过时仍输出大量 React `act(...)` 告警，集中在 TreePanel、TreeLauncher、MergeButton 等异步交互。这些告警会淹没真正回归信号，应一并清理。

## 领队拆分建议

### 第一批：阻断修复

- 前端基础设施：修复 `json()` Header 策略并补集成测试。
- 流式链路：实现真正 cancel，统一首问/追问状态机。
- 数据生命周期：补树恢复能力，核对节点删除/撤销/回收站闭环。
- 路由流程：决定恢复接入还是下线死代码。

### 第二批：核心体验

- 响应式：移动端改为单面板导航。
- 信息布局：修复长分支标题、轮次密度、工具进度。
- 状态管理：消除跨树提示和错误污染。
- 附件语义：统一图片持久化/降级策略。

### 第三批：编辑与知识沉淀

- 选区浮动工具条。
- 笔记编辑/删除/跳转反馈。
- 版本 diff、时间与回退确认。
- 设置作用域和校验。

## 测试数据与清理说明

体验测试创建了树 `UX 体验审查（已验证重命名）`，其中包含多轮短问答、一条整文笔记和一次合并。由于删除接口正是本次发现的阻断缺陷，未绕过产品直接改数据库清理，避免破坏用户数据。修复删除链路后可通过 UI 清理该树。
